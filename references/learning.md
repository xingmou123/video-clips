# 自动复盘、方法更新与团队使用

## 三种信息分别保存

- **通用方法**在本 Skill：选题与剪辑判断、数据口径、证据边界、复验和交付方法。
- **账号与业务约定**在项目 `clip-project.json` 及其引用：目标人群、品牌、账号、素材、CTA 资源、已有客户/订单记录、权限、自动任务与负责人。
- **结果与学习记录**在项目已有工作目录：每条作品、数据快照、实验卡、复盘和当前方法版本。原始客户资料仍在原业务系统。

团队成员拿同一版本的 Skill 和有权限访问的项目入口即可开新聊天，不需要复制旧聊天。团队共用一个方法发布人；剪辑任务各自写自己的作品目录。多人可以提交候选改法，不能同时改当前主片或共享 Skill。

## 自动迭代究竟做什么

Skill 不会自行醒来。使用宿主原生定时任务定期调用 `$video-clips`，在可用的登录态和数据权限内采集、分析、记录。保持机器、应用和必要数据可用；配置成功只证明排程建立。

用户要求周期工作时先检查已有任务的对象和观察点。优先复用其快照，再建立确有必要的补充计划。常见组合是已有单批 24/72 小时观察 + 每周总结 + 已登记作品的 D7/D30 到期检查；按用户需要选择，不强行全开。

定时提示必须包含项目入口、作品范围、观察窗口、准确的数据来源、方法更新权限、落盘位置、通知条件和结束条件。执行时读最新文件，不把提示里一份过时列表永远当完整对象。没有新数据、没有可行动变化时保持安静；有实质结果、故障或需要用户操作时通知。发送飞书、私信等需本任务已有明确授权。

## 学习状态与升级证据

| 状态 | 含义 | 可做的事 |
|---|---|---|
| 候选 | 用户想法、单条观察、历史风格偏好 | 写实验卡，按授权做下一批试验 |
| 已试验 | 真实成片与真实指标齐，适用范围明确 | 复验，解释不确定性与失败样本 |
| 局部采用 | 匹配条件下重复出现有业务意义的改善，负面指标可接受 | 仅在已验证账号/内容范围采用，保留版本 |
| 通用方法 | 多批次或场景支持，或修复可复现的事实/工具错误 | 在授权范围内更新 Skill，说明边界与反例 |
| 撤回 | 证据推翻、效果退化或事实错误 | 恢复上一版，保留原因和失败记录 |

不把一次爆款、创作者个人喜好、相关系数或模型自评当因果证明；也不要求所有小改动都等统计显著。实际标准是证据质量、预期业务影响和试验成本相称。不能因总体播放上涨就升级“引流有效”：有效微信线索及后续质量必须单独核实。

方法更新权限从项目配置读取：

- `propose`：自动复盘、记录候选与下一批建议；正式方法更新由用户决定。
- `bounded_auto`：用户已授权时，可自动更新可回退的剪辑/包装/测量方法，先满足相应证据条件。引流承诺、目标人群重大变化、收费和外部动作权限仍按现有授权。

没有明确授权记录时按 `propose` 执行；不要把没有回复当授权。已有明确授权也不要反复确认。

## 变更落地

内容方法以真实自媒体反馈与对应成片为迭代依据。工具试验另看是否减少制作时间、错误与返工；安装、跑通、模型评分或本地更顺眼不算内容效果改善，不能据此替换既有方法。

本批开始前记方法版本，复盘后记录：依据哪份数据、改变什么判断、适用范围、预期收益、失败/撤回条件和上一个版本。更新共享 Skill 时遵从当前治理位置，由一个写入者先读最新版本、保存可恢复副本、做实际相关验证，再更新版本记录。实验中的方案放项目，不把每周数据追加进 SKILL.md。

可以修复脚本对缺失值的错误、澄清被多次误用的指标；不能让自动化为了“必须有进步”每周改文档。若确认方法无需变化，就记录新证据而保持方法不动。

每周复盘至少回答：本周哪些作品已到观察窗口；实际覆盖多少、还缺多少；哪条在哪一环节较好；哪些旧判断得到支持或被推翻；下一批只试哪几个改动；是否满足正式更新条件。复盘范围由作品登记和平台记录核对，不能只看容易取得的几条。

## 分享方式

将整个 `video-clips` 文件夹安装到宿主支持的 Skills 目录；本机通常为用户技能目录，团队仓库可采用 `.agents/skills/video-clips`。不要同时装两个同名不同版本。用 `$video-clips` 显式调用，或让清晰的任务描述触发。

分享包可以包含匿名模板与脚本，不包含本机路径、私人聊天、学生信息、联系方式、凭证或后台原件。项目配置另由团队自行填写。需要统一升级和连接器分发时，再按宿主官方规范封装插件；不要把一个 ZIP 声称为已上线的团队插件。
